# Linux Deploy CLI 设计说明

> 状态：已实施 | 当前版本：4.1.13

## 一、命令层设计

```
cli.sh [选项] 命令 [参数]

选项：
  -d        调试模式（输出详细日志）
  -t        跟踪模式（set -x）
  -h/--help 帮助

命令：
  config list                         列出全部配置
  config show [名称]                  显示配置详情（名称或 -c 指定）
  config create <名称> [--k=v ...]    新建配置；未指定 CHROOT_DIR 时自动分配独立目录
  config edit [--k=v ...]             修改 -c 指定配置参数
  config copy <源名称> <新名称>       复制配置
  config delete <名称> [--purge]      删除配置（默认保留容器数据；--purge 连同 CHROOT_DIR 一起删除，需二次确认）
  config export <文件>                导出 -c 指定配置
  config import <文件|名称>           导入配置（自动隔离目录）

  deploy [--dry-run] [--yes] [参数]   部署 -c 指定配置（debootstrap 安装 + 组件配置）
  start [--dry-run] [--yes]           启动 -c 指定容器
  stop                                停止 -c 指定容器
  status                              查看 -c 指定容器状态
  shell [-u 用户] [命令]              进入 -c 指定容器
  check                               自检（环境/配置/依赖/目录权限）
  help [组件...]                      帮助

  import <归档>                       导入 rootfs 到 -c 指定容器
  export <归档>                       导出 -c 指定容器为 rootfs 归档
  mount / umount                      挂载/卸载 -c 指定容器
```

## 二、核心机制

### 1. 显式指定配置（-c）
- 无配置锁：所有容器操作命令通过 `-c <配置名>` 显式指定操作配置。
- 未带 `-c` 时容器操作命令拒绝执行并提示；`config list/create/copy/delete/import` 等配置管理命令自带配置名，无需 `-c`。
- 所有操作类命令输出顶部固定显示：`操作配置: <名称> (路径: ...)`。

### 2. 配置隔离
- 新建配置若未显式指定 `CHROOT_DIR`，自动生成 `<ENV_DIR>/builds/<配置名>`，配置间物理隔离。
- 既有配置保留其原有 CHROOT_DIR，迁移需用户手工确认。

### 3. 安全护栏
- 部署前：目标目录存在且非空 → 拒绝执行并提示（除非 `--yes` 且用户显式确认）。
- 部署前：显示将要执行的安装动作摘要，要求确认（`--yes` 跳过）。
- `--dry-run`：只输出动作计划，不执行。
- 删除配置/清空目录前一律确认。

### 4. 自检 check
输出中文结果，每项一行，退出码反映结果：
- 运行身份（root）、核心工具（wget/curl/ar/tar/xz/zstd/dpkg-deb）
- debootstrap 文件完整性、操作配置可读性、CHROOT_DIR 权限
- 挂载能力（/proc /sys /dev）、SELinux、loop 设备、binfmt_misc

## 三、运行状态检测（ldstatus）

- Android 上每次 `su -c` 调用处于独立 mount 命名空间，挂载可见性不能作为
  运行状态依据。
- `core/ldstatus` 组件在容器内启动一个 setsid 脱离的标记进程
  （`/usr/local/sbin/ldstatus`，`exec -a ldstatus`），PID 写入容器磁盘
  `/run/ldstatus/pid`（跨命名空间可见）。
- `status` 通过 `ps -A` 按 PID+进程名匹配判断 running，跨命名空间可靠；
  `mounted` 表示当前命名空间内可见的挂载状态，二者独立输出。

## 四、debootstrap 适配（官方 1.0.144 为根基）
- 整体替换 `include/bootstrap/debian/debootstrap/`。
- 集成方式：`DEBOOTSTRAP_DIR` 环境变量 + source 执行 + `--foreign --extractor=ar --no-check-gpg` + 二阶段 `chroot_exec /debootstrap/debootstrap --second-stage`。
- 非空目录保护在 CLI 层执行。

## 五、Debian 组件适配
- 默认 SUITE=trixie（Debian 13）。
- 默认源保持官方 `https://deb.debian.org/debian/`（网络受限时通过 --source-path 覆盖为镜像）。
- include/exclude 包清单与 apt 配置适配 trixie。

## 六、范围与不变量
- 只做 arm64；x86/arm32/unshare/Fedora/Docker/CentOS/Slackware 不做。
- 启动方式固定 chroot。
- 前端 app 与 CLI 通过 `--json` 协议对接；CLI 保持 shell 脚本，输出稳定、退出码语义清晰。
- 全中文注释与日志；变量名/路径/参数保持 ASCII。

## 七、版本管理
- 本地 git，小步提交；当前版本 4.1.13，与 App versionName/EXTRACT_MARKER 保持一致。
