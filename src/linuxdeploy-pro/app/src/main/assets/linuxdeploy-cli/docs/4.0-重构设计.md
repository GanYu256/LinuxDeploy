# Linux Deploy CLI 4.0 重构设计

> 状态：已确认实施 | 基线：app 锁定版 79924f593556（VERSION 2.5.1）
> 目标：只维护 CLI，全部工作在本机（k30p），本地 git 版本管理，不推远程

## 一、事故根因（旧版 2.5.1）

1. `config -i 名称` 的语义是“把指定配置内容合并写回当前配置”，不是“切换配置”，极易误操作。
2. 当前配置没有持久化概念，每次运行都要靠 `-p` 参数或默认值推断，切换即丢失。
3. 所有配置共享默认 `CHROOT_DIR=${ENV_DIR}/mnt`，新配置天然指向旧容器目录，存在被误清空的风险。
4. debootstrap `--foreign` 阶段对目标目录**无空目录检查**，官方仅在 `kill_target` 阶段检查。
5. rootfs 组件 `TARGET_TYPE=directory` 直接 `rm -rf` 目标目录，无任何确认。

## 二、4.0 命令层设计

```
cli.sh [选项] 命令 [参数]

选项：
  -d        调试模式（输出详细日志）
  -t        跟踪模式（set -x）
  -h/--help 帮助

命令：
  config list                         列出全部配置
  config show [名称]                  显示当前（或指定）配置详情
  config use <名称>                   切换当前配置（即锁定，持久化到 .current）
  config create <名称> [--k=v ...]    新建配置并自动切换；未指定 CHROOT_DIR 时自动分配独立目录
  config edit [--k=v ...]             修改当前配置参数
  config copy <源名称> <新名称>       复制配置
  config delete <名称> [--purge]      删除配置（默认保留容器数据；--purge 连同 CHROOT_DIR 一起删除，需二次确认）
  config export <文件>                导出当前配置
  config import <文件|名称>           导入配置（自动隔离目录）

  deploy [--dry-run] [--yes] [参数]   部署当前配置（debootstrap 安装 + 组件配置）
  start [--dry-run] [--yes]           启动当前配置
  stop                                停止当前配置
  status                              查看当前配置状态
  shell [-u 用户] [命令]              进入当前配置容器
  check                               自检（环境/配置/依赖/目录权限）
  help [组件...]                      帮助

  import <归档>                       导入 rootfs 到当前容器
  export <归档>                       导出当前容器为 rootfs 归档
  mount / umount                      挂载/卸载当前容器
```

## 三、核心机制

### 1. 切换即锁定
- 当前配置名持久化在 `CONFIG_DIR/.current`。
- 每次运行读取该文件确定当前配置；`config use` 写入新值。
- 所有操作类命令输出顶部固定显示：`当前配置: <名称> (路径: ...)`。

### 2. 配置隔离
- 新建配置若未显式指定 `CHROOT_DIR`，自动生成 `<ENV_DIR>/mnt/<配置名>`，与老配置物理隔离。
- 原有配置（老 .conf）显式保留其 CHROOT_DIR，迁移需用户手工确认。

### 3. 安全护栏
- 部署前：目标目录存在且非空 → 拒绝执行并提示（除非 `--yes` 且用户显式确认）。
- 部署前：显示将要执行的安装动作摘要，要求确认（`--yes` 跳过）。
- `--dry-run`：只输出动作计划，不执行。
- 删除配置/清空目录前一律确认。

### 4. 自检 check
输出中文结果，每项一行，退出码反映结果：
- 运行身份（root）、核心工具（wget/curl/ar/tar/xz/zstd/dpkg-deb）
- debootstrap 文件完整性、当前配置可读性、CHROOT_DIR 权限
- 挂载能力（/proc /sys /dev）、SELinux、loop 设备、binfmt_misc

## 四、debootstrap 适配（官方 1.0.144 为根基）
- 整体替换 `include/bootstrap/debian/debootstrap/`（已提交 dfd7411）。
- 保留集成方式：`DEBOOTSTRAP_DIR` 环境变量 + source 执行 + `--foreign --extractor=ar --no-check-gpg` + 二阶段 `chroot_exec /debootstrap/debootstrap --second-stage`。
- 非空目录保护放在 CLI 层（debootstrap 官方仅在 kill_target 检查）。

## 五、Debian 组件适配（P3）
- 默认 SUITE=trixie（Debian 13）。
- 默认源保持官方 `https://deb.debian.org/debian/`（k30p 网络被劫持时通过 --source-path 覆盖为镜像）。
- include/exclude 包清单核对，apt 配置适配 trixie。

## 六、范围与不变量
- 只做 arm64；x86/arm32/unshare/Fedora/Docker/CentOS/Slackware 不做。
- 启动方式固定 chroot。
- 前端 app 后续重构；CLI 保持 shell 脚本，输出稳定、退出码语义清晰，方便前端适配。
- 全中文注释与日志；变量名/路径/参数保持 ASCII。

## 七、版本管理
- 本地 git，小步提交，里程碑打 tag。
- 当前分支 cli-4.0；计划 tag：cli-4.0-debian13-beta1。
